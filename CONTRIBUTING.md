# Contributing

Issues and pull requests are welcome. Benchlight is a building-block library with one visual
identity, so open an issue before a large change or a new component. Contributions are under the
project's MIT license.

Benchlight needs [bun](https://bun.sh) 1.4.2 or newer (pinned in `package.json`). Docker is only
needed for the Linux screenshot baselines and `lint:workflows`.

```sh
bun install
bun run check
```

## Development

| Command                                            | What it does                                                                                                                                                                                       |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun run check`                                    | lint, format check, typecheck, unit tests (incl. freshness, contrast, budgets)                                                                                                                     |
| `bun run fixtures`                                 | packs the working tree, builds and verifies the Nuxt and Vite fixtures; not in `check`, runs in CI                                                                                                 |
| `bun run lint:workflows`                           | actionlint over `.github/workflows` (needs Docker)                                                                                                                                                 |
| `bun run build`                                    | regenerates tokens, theme, `js/prepaint-script.mjs`, `dist/` (CSS, JS), and `API.md`                                                                                                               |
| `bun run playground`                               | component showcase on Vite                                                                                                                                                                         |
| `bun run test:visual`                              | Playwright axe, keyboard and screenshot checks of the playground (also run in CI on Linux)                                                                                                         |
| `bunx playwright test tests/visual/stress.spec.ts` | the stress suite (desktop-light only); view the page with `bun run playground` at `/stress.html`. `STRESS_BREAK=overflow\|stack\|small\|overlap` breaks layout on purpose to prove the checks bite |
| `PW_PORT=4277 bun run test:visual`                 | preview port override, so Playwright runs in parallel worktrees do not share a server (default 4173)                                                                                               |
| `scripts/visual-linux.sh`                          | the same suite in CI's Linux image via Docker; add `--update-snapshots` to re-record Linux shots                                                                                                   |
| `bun scripts/fetch-fonts.ts`                       | re-fetches the pinned Google font files and `css/fonts.css`                                                                                                                                        |
| `scripts/subset-fonts.sh`                          | re-cuts the compact font subsets with fontTools                                                                                                                                                    |

## Generated files

`dist/` (the minified CSS bundles and `dist/tokens.js`) is generated by `bun run build` and committed
on purpose: git installs do not run build scripts. Freshness tests in `bun run check` fail if it is
stale, so rebuild before committing token or CSS changes.

## API contract

`API.md` is generated by `bun run build`. It lists package exports, `dist/` files, runtime exports,
exported types with their shapes, components (props, slots with their props, events), CSS classes,
tokens, script-set `data-*` attributes, hook-only classes and CSS hooks. Review a diff in it as the breaking-change checklist before
tagging.

## Adding a component

1. `css/components/x.css`, in `@layer components`, prefixed `bl-`.
2. Add it to `MODULES` in `scripts/lib/modules.ts`; the order is pinned by `tests/css-conventions.test.ts`.
   If it needs another module's CSS, declare that in `REQUIRES` in the same file (the bundle CLI
   warns when a requirement is missing).
3. Import it in `css/index.css`, in the same order.
4. `vue/components/BlX.vue`, with an inline literal `defineProps` type (the SFC compiler can only
   expand an imported props type when TypeScript is installed; `tests/vue/sfc-props.test.ts` enforces it). Export it from `vue/index.ts` and cover it in
   `tests/vue/barrel.test.ts`.
5. A new composable also goes into `AUTO_IMPORTS` in `nuxt/module.ts`.
6. Add it to the playground (`playground/src/App.vue`).
7. Add stress cases (long content, narrow container, flex/inline host) to `playground/src/Stress.vue`.
8. `bun run build` regenerates `dist/` and `API.md`.
9. Re-record the baselines on both platforms: `bunx playwright test --update-snapshots -g "renders every"`
   and `scripts/visual-linux.sh --update-snapshots -g "renders every"`.
10. One commit per component.

## Size guards

`dist/benchlight.min.css` has no size cap; check it with `wc -c dist/benchlight.min.css`. The
compact font subsets stay under 23,552 B in total (`tests/fonts.test.ts`); the guard is raised in
round KiB when legitimate work needs it, and every raise gets a CHANGELOG line.

## Releasing

`bun pm pack` decides what ships: the `files` list in `package.json` plus the always-included
files. Neither the npm package nor the git release tags contain tests or the playground.

1. In one `chore: release vX.Y.Z` commit, bump `version` in `package.json` and add the entry to
   `CHANGELOG.md`. The playground shows the version, so re-record its baselines on both platforms
   (`-g "renders every"`, see Adding a component).
2. `bun run build && bun run check && bun run fixtures`.
3. Push `main`, wait for CI, then push the source tag:
   `git tag -a src-vX.Y.Z -m src-vX.Y.Z && git push origin src-vX.Y.Z`. Never push `vX.Y.Z` yourself.
4. The `release` workflow checks that the tag is on `main` and matches `package.json`, runs the
   checks, builds the slim tree from `bun pm pack`, commits it to the `release` branch and tags that
   commit `vX.Y.Z`. A separate job installs the tag from git and verifies it is slim.
5. Publish to npm with the manual `publish` workflow: "Run workflow", pick the `src-vX.Y.Z` tag
   under "Use workflow from", tick `confirm` and type the version. It publishes with provenance
   through npm trusted publishing (no token). The protections listed at the top of
   `.github/workflows/publish.yml` must be in place before the first run.

Renaming or removing a token, class, prop, custom property or the appearance attribute/key is a
breaking change (`BREAKING CHANGE:` footer; minor bump while 0.x).
